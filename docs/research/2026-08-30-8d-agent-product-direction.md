# 8D Agent 产品方向：让人只做核心的事

> 整体目标：**小白可以轻松使用；有经验的人用起来更方便；减少繁杂、重复的工作，把精力放回核心事情上。**

这份文档把上一份可行性研究收成可执行的产品原则。它不改变「不能替人编造根因」的底线，但纠正一个容易走偏的点：如果只做新手向导，熟手会觉得啰嗦；如果只做专家表单，小白仍然过不了第一关。

新手与熟手的具体痛点见 [痛点调研](2026-08-30-8d-practitioner-pain-points.md)。调研后多了三条硬约束：新手主交付是现场采集卡，不是漂亮报告；熟手主交付是去掉第二次劳动，不是再讲 5Why；相似案件只复用结构，不复用未验证根因。

---

## 1. 目标怎么落到产品上

三句话，对应三个设计约束：

| 目标 | 产品必须做到 | 产品绝不能做成 |
| --- | --- | --- |
| 小白轻松用 | 不用先学 8D 术语也能走完；每一步解释「为什么问这个」；错写法被拦住并告诉怎么改 | 把用户丢进空白大表，或生成一份他看不懂对错的「专业作文」 |
| 熟手更方便 | 同一套数据，可以跳过讲解、粘贴即填、复用历史案件、一键换模板、一键过评审 | 强迫资深 QE 走 40 个新手问答 |
| 人做核心事 | 自动处理格式、改写、检查、翻译、映射、提醒、导出 | 替人决定现场事实、未验证的根因、未实施的对策 |

**核心事情**不是「把格子填满」，而是只有人能做、做了对质量真正有用的那几件事：

1. 到现场看现物、确认事实（三现）
2. 验证根因（复现、对比、实验、数据）
3. 选定并推动真正的工程/系统对策
4. 对客户和内部签字负责

**繁杂、重复的事**是每次客诉都要再做一遍、但不需要重新思考的事：

- 从投诉邮件/微信截图里抽出客户、零件、缺陷、批次
- 把口语改写成 5W2H / 客户口吻
- 套不同主机厂模板、中英对照、邮件草稿
- 组团队通讯录、上次用过的人
- 遏制动作清单、库存位置检查表
- 缺字段、禁区词、双根因是否齐全
- D7「该改哪些文件」清单
- 时效倒计时、中间版/终版导出
- 相似历史 8D 的结构复用（不是复用未经验证的结论）

判断标准：**这件事如果换一个同类客诉还会原样再做一遍，就该交给工具；如果必须去产线或实验室才能知道答案，就必须留给人。**

## 2. 两种人，同一份案件

不要做两个产品。做**一份结构化案件 + 两种速度的入口**。

```
        粘贴投诉 / 上传照片 / 打开旧案
                     │
                     ▼
              结构化 Case 对象
              （唯一真相来源）
                 /        \
                /          \
        向导速度              工作台速度
      （小白默认）            （熟手默认）
     一次一问                整页可编辑
     带例子与反问            快捷键、粘贴、复用
     讲解可展开              讲解默认收起
                \          /
                 \        /
                     ▼
           同一套门禁与评审
                     ▼
        中间版 / 终版 / 多模板导出
```

经验值可以很轻：第一次用向导；连续做对三次或用户主动切换后，默认进入工作台。熟手任何时候可以「展开这一步的教练」；小白任何时候可以「我已经知道，直接填」。

**关键：门禁不因人而放松。** 熟手可以跳过讲解，不能跳过「流出原因未填」「根因未验证」就关闭案件。方便来自少点废话，不是来自少点纪律。

## 3. 三种交互路径（取舍）

### 路径 1：只做新手问答

小白友好，熟手会弃用。质量部门里真正每天写 8D 的人往往是熟手——丢掉他们，产品只剩培训工具。

### 路径 2：两套完全分开的界面

开发和维护成本翻倍，两套数据容易不一致。不推荐。

### 路径 3：渐进披露，一套对象两种速度（推荐）

- 默认按「你现在卡在哪一步」给最短路径
- 解释、例子、反问全部可折叠
- 熟手用「导入投诉 → 确认抽取 → 补缺口 → 导出」四步走完 D0–D3
- 小白在同一流程里被多问几句「这个数你是量的还是估的」

这是唯一同时满足「小白轻松、熟手更快」的做法。

## 4. 工具替人做的，和工具只帮忙的

### 4.1 应该几乎全自动（人只点确认）

| 工作 | 熟手痛点 | 产品行为 |
| --- | --- | --- |
| 抬头信息 | 每次重填客户/零件/产线 | 从邮件、历史案件、客户档案预填 |
| 语言润色 | 口语变正式中英文 | 改写，并高亮改动；数字不得被改 |
| 模板换皮 | 同一内容贴三个客户表 | 一份 Case，多模板渲染 |
| 缺项检查 | 交出去才被 SQE 退 | 实时红黄灯 + 一键定位 |
| 禁区拦截 | 「加强培训」写顺手了 | 立刻挑战，给系统层问法 |
| 时效与中间版 | 24h 先交一版 | 一键出 D3 中间版，标清待补 |
| 邮件/门户话术 | 每次重写客套句 | 按客户档案出草稿 |
| D7 文件清单 | 想不全要改什么 | 按根因类型生成检查表（人勾完成） |
| 相似案件 | 记得上回折弯件怎么写 | 只复用结构与检查项，不复用未验证结论 |

### 4.2 应该教练，但不代劳

- D2 的 Is/Is-Not：帮他想到要问「哪里没有」，格子仍由现场填
- D4 的 5Why：追问「这还是人因，系统为什么允许」；验证数据必须人贴上来
- D5 对策强度：排出「防错 > 工艺 > 制度 > 培训」，选择权在团队

### 4.3 永远不自动完成

- 发明批次号、不良率、验证周期
- 在没有证据时宣布根因
- 把遏制写成永久对策并关闭案件
- 替质量经理在客户门户提交

## 5. 主路径（两种人各走一遍）

### 小白：第一次客诉，被催 24 小时 D3

1. 粘贴客户投诉，上传两张不良照片
2. 系统抽出已知事实，用大白话列出「还缺 4 项：批次、发现工位、不良数量、库存位置」
3. 用选项问遏制：客户现场 / 在途 / 成品仓 / 线边，每一项生成动作建议
4. 用户确认「已隔离 3 托、客户处已安排分选」后，10 分钟导出中间版
5. 第二天再打开，向导带他做 Is/Is-Not 和双 5Why，卡住就给例子
6. 写到「操作工没按作业」时被拦住，换成「为什么系统允许没按作业也能做下去」
7. 验证数据和对策由团队补完后，一键出终稿 + 内部评审意见

小白的轻松，来自**不用决定下一步问什么**。

### 熟手：同类缺陷第三次，要赶三个客户模板

1. 「从相似案件创建」，带出团队、产线、控制计划编号、常见遏制项
2. 粘贴新投诉，确认抽取结果，改三个数字
3. 工作台直接改 D2/D3，教练面板收起
4. 跑一遍评审：流出原因还空着 → 补一句并挂检测工位照片
5. 导出 VW / 通用 / 内部三种模板，中英各一份

熟手的方便，来自**不再做第二次的格式劳动**。

## 6. 成功标准（按目标验收）

相对上一份研究，成功标准从「小白能写完」扩成三条，缺一不可：

1. **小白：** 没学过 8D 的人，能在催单当天独立产出不丢人的 D3 中间版；终稿不会出现「操作工 + 加强培训」作为唯一闭环。
2. **熟手：** 从投诉到可发送的中间版，重复劳动时间明显下降（目标：抬头、改写、套模板、自检从小时级降到分钟级）。
3. **核心时间被保护：** 用户把省下的时间用在现场确认和根因验证上；产品用「待验证」清单把人推回产线，而不是推回 Word。

失败形态仍然是：三分钟生成排版精美、内容虚构的 PDF。新增一种失败形态：**把熟手当小白训，或把小白当熟手扔空表。**

## 7. 对实现范围的含义

痛点调研后的功能先后：P0 中间版 + 缺口清单、禁区评审、投诉抽取改写；P1 多模板/中英、现场采集卡、提交前预审；P2 相似案件结构复用、措施待办；P3 门户直连、自动改 FMEA 主文件。不按「关闭速度」优化，不对所有异常强制满配 8D。

MVP 仍然是「门禁教练 + 报告编译器」，但第一期就要同时具备：

- 向导 / 工作台切换（可以很朴素：问答 vs 整页表单）
- 投诉文本抽取 + 人确认
- 中间版导出
- 禁区评审
- 至少一种专业模板

历史案件复用、多 OEM 模板、客户邮件草稿，是「熟手更方便」的第二刀，但数据模型第一期就要按「可复用」来建，避免日后推倒。

---

## 8. 一句话定位

> 8D Agent 是质量团队的书记员、翻译和质检员：把每次都要做的杂事拿走，把必须亲自看、亲自证、亲自拍板的事留下来；小白被领着走，熟手自己跑，交出的是同一份经得起客户看的报告。
