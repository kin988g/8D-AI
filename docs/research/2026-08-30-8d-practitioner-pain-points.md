# 新手与熟手做 8D 时的痛点调研

> 调研目的：在写实现规格之前，先分清两种人到底卡在哪。否则产品会做成「对小白仍太硬、对熟手又太啰嗦」的中间态。  
> 结论先行：**新手的痛是认知和恐惧；熟手的痛是批量和协调。两边共同的痛是「一个人填表 + 24 小时交卷 + 证据散落」。工具应分别打这两套痛，而不是只加速写字。**

---

## 0. 材料从哪来、缺什么

本调研综合了：

- 质量方法与实操指南（ASQ、福特 G8D、VDA、电子/汽车厂 8D 退件指南）
- 一线质量工程师公开陈述（LinkedIn 上 QE 对「写报告不解决问题」的复盘）
- SQE 日常工时拆解（评审弱 SCAR / 8D 是供应商质量岗的大头时间）
- 中文制造业实务（把 8D 当检讨书、人手不足、中英模板、催部门）
- 8D 软件与智能体厂商对其客户痛点的描述（邮件飞来飞去、Excel 管进度、知识不沉淀）
- 学术观察：对偶发小问题强制完整 8D，会导致团队厌弃方法本身（8D fatigue）

**没有做的事：** 还没有对目标工厂做结构化访谈。下列痛点是跨来源反复出现的模式，可作为产品假设；上线后应用真实案件日志验证优先级。

**必须先接受的时间结构：**  
一次认真的客诉 8D 通常不是「写 2 小时」。有实务材料把节奏拆成 30–60 天、约 4 次工作坊（合计 12–15 小时），**全部调查大约 60–100 人时**，其中约 80% 发生在会与会之间：收数据、盯遏制、做试验、改控制计划。报告写作只是冰山露出的那一块，却是客户催的那一块。

因此：

| 角色 | 真正的瓶颈 | 如果产品只优化「写得快」 |
| --- | --- | --- |
| 新手 | 不知道该调查什么、怕写错被退 | 会更快产出不合格报告 |
| 熟手 | 并行多案、换皮、催人、找旧案 | 只省下他们本来就最快的那一段 |

---

## 1. 两边都痛：8D 在工厂里的真实处境

这些不是能力问题，是工作系统设计问题。新手和熟手每天都撞上。

### 1.1 截止比真相更早到达

客诉进来，D3 常见要求 24–48 小时（部分门户更短）。根因还没摸到，客户已经要「书面保证」。于是所有人被迫先交一版「看起来完整」的东西。新手用猜测填满；熟手用上份报告改三个数字。两种人都会在截止压力下牺牲 D4 质量。

### 1.2 团队是挂名，质量一个人填表

客户最怕、工厂里最常见：D1 名单很漂亮，实际只有 QE 在写。工艺、生产「人不在场」或开会时人在心不在。报告变成一个人的事后作文。Mobile2b、多名 QE 都指出：一人事后填表，根因一定是猜的。

### 1.3 事实不在一个地方

投诉在邮件/微信，批次在 ERP，检验在 MES 或纸质，照片在手机，措施进度在群里。D2 写不清，往往不是不会 5W2H，而是 **How many / 批次 / 库存位置当晚凑不齐**。电子行业指南特别点出：How many 最容易写成「少量不良」，客户立刻怀疑调查不全面。

### 1.4 模板错了，内容看都不看

「客户给了表就必须用客户的表。」用错模板会在读内容之前被退回，钟还在走。同一内容要变成 VW / 福特 / 内部 / 中英双语，是纯损耗。

### 1.5 结案不等于解决

公开讨论里重复出现同一句：8D 关了，三个月后同样问题回来。原因几乎固定——根因停在症状、遏制当纠正、D6 无数据、D7 没改 FMEA/控制计划。熟手知道这一点，但仍常因结案 KPI 和时间不够而跳过。新手不知道这一点，会把「已关闭」当成成功。

### 1.6 小题大做把方法做臭

对偶发、原因已知的小问题强制完整 8D，团队会认为 8D 是官僚。下次真遇到系统性问题，也用「操作工+培训」糊弄。这是方法失效的组织原因，不只是个人水平。

## 2. 新手痛点：不会想，怕被骂，把 8D 写成检讨书

新手画像：转岗 QE、应届、被临时抓来回客诉的生产主管、一人兼多职的供应商质量员。他们缺的不是 Word，是**心理模型**。

### 2.1 把 8D 当成认错信

中文实务反复写到：大量报告被退，不是问题没处理，是报告没有说服力；工程师在写「检讨书」而不是工程文档。语气是道歉和保证，不是证据链。客户要的是「读完 D7 是否相信不会再发」，不是态度。

**产品含义：** 默认文风应是事实句，不是「深感抱歉、将加强管理」。态度句可单独放进邮件草稿，不要污染 D2–D7。

### 2.2 不知道下一步该问什么

D2 需要 5W2H 和 Is/Is-Not，但没人教「今晚应该去产线问哪 8 个问题」。于是对着客户原话复制：「支架有质量问题。」不知道「哪里没有发生」比「哪里发生了」更有信息量。

**产品含义：** 向导的价值是**生成今晚的现场问题清单**，不是生成今晚的假报告。

### 2.3 分不清四层措施

紧急响应、遏制、纠正、预防在脑子里是一锅粥。最典型：D5 仍写 100% 全检或加强巡检。客户一眼看出：你只是继续花钱拦，没有消灭原因。

### 2.4 不会双根因，5Why 两层就停

台湾/大陆工厂高频退件第一名：**只写发生原因，不写流出原因**。第二名：根因停在「人」。5Why 停在「参数没校准 / 员工没按 SOP」，没有问到「为什么系统允许这样」。鱼骨图六格都填了，但是装饰，没有用 Is/Is-Not 筛假说，也没有验证。

有公开案例称：把原因写成「培训不足」可导致罚款甚至取消供方资格。新手不知道这句话有多致命。

### 2.5 用谎言填截止（然后用更多谎圆）

培训内容里会单独强调：8D 里不要说谎。截止压力下，新手最容易编数量、编「已培训」、编验证周期。一个假数字会逼出整链假故事，被客户一次问穿。

**产品含义：** 缺字段必须允许「待补充」并导出中间版；禁止用生成模型补数字。

### 2.6 怕客户、怕内部、怕现场

- 怕 SQE 追问，所以写得越空越「安全」  
- 怕指责产线，所以根因推向「操作工」或反过来谁也不敢写系统问题  
- 怕去现场显得外行，所以坐在工位上写  

结果是报告和产线是两张皮。

### 2.7 英语和术语是第二座山

外资客户要全英文或双语。新手连 Occurrence / Escape / ICA / PCA 都分不清，更不要说把「磕伤」写成客户能审的工程英语。内部缩写客户看不懂，也会被退。

### 2.8 被退一次就进入创伤循环

第一次按网上模板交，被退「根因是人」「没有流出分析」。第二次更不敢写具体，更空，再被退。信心崩了，开始央求熟手代写——熟手的重复劳动反而增加。

## 3. 熟手痛点：会做，但被复制、催办和换皮耗死

熟手画像：做过几十份、知道客户会卡哪、能主持 D4，但同时挂着多份未结 8D。他们的痛苦不是「D2 怎么写」，是**规模和系统**。

### 3.1 写作不是大头，翻译和换皮才是

熟手 20 分钟能写完合格 D2。接下来的 2 小时可能花在：

- 把同一段话贴进客户 Excel 的合并单元格  
- 中译英、改称谓、改日期格式  
- 调行高、塞照片、对齐鱼骨图  
- 上传门户、字段对不上再改  

「用错模板先退回」对他们是纯时间税。

### 3.2 并行多案，进度在脑子和微信里

TeamGuru / 金蝶等描述的客户现场：邮件在部门间飞，三天后客户再问，还在拼事实。熟手每天大量时间用于：谁还没回批次、分选数、试验照片。不是分析能力不够，是**书记和催办没有工具**。

SQE（客户侧）一周可花 10–15 小时审弱 8D、追逾期阶段。供应商侧的镜像就是：熟手反复改同一份被退报告。退件循环是双方的重复劳动。

### 3.3 最诱惑的捷径：改上一份

「问题描述从投诉复制；根因从类似件复制。」LinkedIn 上的 QE 说模式总是一样：不看过程、不够问、会议里的人并不在场，系统一过载就找捷径。客户能在一分钟内看出模板 8D。更糟的是：复制把上一次的盲区遗传下来（FMEA 复制粘贴是同一病理）。

**产品含义：** 复用必须是结构、检查项、团队、控制计划编号；**禁止一键复用未经验证的根因结论**，并明确标出「这是旧案假设，必须用本案数据重验」。

### 3.4 知识在人脑子里，不在可检索处

同类折弯、同类贴偏，熟手「依稀记得去年那份」。但旧 8D 在共享盘、个人邮箱、离职同事电脑里。D7 写了「纳入经验教训」，下次却检索不到。于是每次从零分析，或凭记忆复用——两者都贵。

### 3.5 措施写得出，落不了地

D5 写了防错和改夹具，但要预算、要设备、要工艺签字。Champion 若只是挂名，对策停在「待批准」。熟手变成项目经理：催、升级、收集「已完成」截图。QE 公开说最大挑战常常是 **验证对策**，不是想对策。

### 3.6 结案 KPI 与职业自尊打架

组织考核「关闭时效」，客户考核「是否再发」。熟手知道该更新 PFMEA，但改 FMEA 是另一场政治（谁改、谁签、影响到哪个项目）。于是 D7 写成空话以求关闭。三个月后再发，熟手比新手更挫败——他们知道自己在交纸面胜利。

### 3.7 被当成「全厂 8D 代写」

新手一被退，案子甩给熟手。熟手的时间从「现场和验证」被挤成「润色别人的检讨书」。组织没有教练机制，只有英雄救火。

### 3.8 8D 用滥之后的厌倦

学术和实践都观察到：随机差错也要完整 8D → 团队认为方法无用 → 复杂问题也敷衍。熟手要的其实是**分级**：小问题 5Why/A3，客诉和再发才上满配 8D。没有分级，熟手会讨厌任何 8D 工具。

## 4. 按步骤看：谁痛、痛什么

| 步骤 | 新手卡点 | 熟手卡点 | 工具该接手的 |
| --- | --- | --- | --- |
| D0 | 不知道要不要上 8D，直接开写 | 被迫对小事做满 8D | 分级建议；紧急动作清单 |
| D1 | 只会填质量部自己 | 名单复制，人仍不来 | 角色推荐；会议预读包 |
| D2 | 复制投诉原句；数量含糊 | 等数据、改客户格式 | 抽取 + 缺口清单；Is/Is-Not 空表 |
| D3 | 写成「将执行」；漏库存位置 | 四地库存数要不到 | 位置检查表；中间版一键出 |
| D4 | 人因、单根因、5Why 两层 | 主持会议但记录散、旧案难找 | 双链教练；禁区拦截；结构复用 |
| D5 | 培训/加检当永久对策 | 对策强度知道，落地要催 | 强度层级提示；任务拆条 |
| D6 | 「效果良好」 | 要连续批次数据、撤遏制无人提醒 | 验证指标模板；到期提醒 |
| D7 | 不知道 FMEA 是什么 | 知道但改文件链路长 | 文件/横向检查清单 |
| 导出 | 不会英文、不会选模板 | 同一内容打三份 | 多模板、双语、预审 |

## 5. 痛点背后的三句人话

1. **新手缺的是问题清单和刹车，不是文笔。** 他们怕的是「交出去被退」，所以宁可写空。要给他们：今晚问什么、哪些话绝对不能写、缺数据可以先交中间版。  
2. **熟手缺的是书记员和复印机，不是教练。** 他们怕的是「今晚还要改第三份客户表、还要催工艺回照片」。要给他们：抽取、换皮、双语、预审、旧案结构、待办。  
3. **两边都被「一个人 + 一张表 + 一个截止」伤害。** 若不把证据和任务从微信里捞出来，任何生成器都只是把混乱打印得更漂亮。

## 6. 对产品的修正（比上一版更硬）

上一版方向「一套案件、两种速度」仍然对。痛点调研要求加上三条，否则会做错功能：

### 6.1 新手模式的主交付不是报告，是「下一步去现场干什么」

每个向导步骤结束，应输出一张可打印/可转发的 **现场采集卡**（问什么、拍什么、数什么）。没有这张卡，向导只是把填表搬到了对话框。

### 6.2 熟手模式的主交付是「减少第二次劳动」，不是再讲一遍 5Why

默认收起讲解。打开案件就应看到：已抽取事实、缺口、相似案件结构、客户模板、预审红灯。5Why 教练是按需展开，不是必经动画。

### 6.3 复用要设计成「防遗传盲区」

相似案件可以带：团队、产线、控制点、遏制菜单、D7 文件列表。不可以默认带：根因原句、未验证对策。复制旧根因必须二次确认 + 本案验证钩子。

### 6.4 明确不做的「假效率」

- 不按「关闭速度」优化（那会强化纸面胜利）  
- 不对所有异常强制满配 8D（会加重 8D 厌倦）  
- 不在截止前用模型补全空数字

## 7. 建议的痛点优先级（实现时的先后）

按「出现频率 × 被工具真实减轻的程度」：

| 优先级 | 痛点 | 主要受益人 | 为何先做 |
| --- | --- | --- | --- |
| P0 | 24h 要交、事实不全 | 双方 | 中间版 + 缺口清单，挡住编造 |
| P0 | 人因 / 无流出 / 培训当对策 | 新手为主，熟手少返工 | 禁区评审，减少退件循环 |
| P0 | 投诉抽取与专业改写 | 双方 | 去掉最无聊的第一小时 |
| P1 | 多模板 / 中英 | 熟手 | 纯重复劳动 |
| P1 | 现场采集卡 | 新手 | 把人推回产线 |
| P1 | 预审打分（按退件清单） | 双方 | 在客户退之前自己退 |
| P2 | 相似案件结构复用 | 熟手 | 依赖案件库，模型要先建对 |
| P2 | 措施待办与催办 | 熟手 | 接近轻量项目管理，第二期也可 |
| P3 | 门户直连、FMEA 主文件写入 | 熟手 | 集成重、责任大 |

## 8. 一句话对照

| | 新手 | 熟手 |
| --- | --- | --- |
| 内心独白 | 「我不知道怎样才算写对，被退好丢人。」 | 「我知道怎样才对，但今晚没时间再排第三份表、再催一次分选数。」 |
| 失败样子 | 检讨书 + 人因 + 加强培训 | 改旧案 + 换皮出错 + 结案后还再发 |
| 工具该让他感觉 | 「原来今晚只要去问这 8 个问题，缺的可以先交中间版。」 | 「数字我改完，模板和英文和自检已经好了，我去产线。」 |

8D Agent 若只让新手「写得像那么回事」，会害他们；若只让熟手「再学一次 8D」，会被关掉。要对准这两句内心独白，产品才算打在痛上。
